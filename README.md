# ALTUM Consulting — Digital in Motion / v4

Адаптивный коммерческий одностраничный сайт на **Next.js, React, TypeScript и Motion for React**. Вторая версия использует новые объёмные CGI-иллюстрации, созданные встроенным ImageGen, и отдельные программные motion-сцены. Логотип ALTUM взят из оригинального предоставленного PDF и не перерисовывался.

Изображения сами по себе статичные. Реальная анимация работает в браузере на Motion/CSS/SVG: интерфейсы, курсор, прогресс, отдельный конь, график, камера-композиция, световые линии. WebM/MP4-ролики не создавались. WebGL и тяжёлый 3D-движок не требуются.

## Запуск

Node.js 20.9+ (рекомендуется актуальная LTS), npm:

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000. Production:

```bash
npm run typecheck
npm run build
npm start
```

`build` создаёт статический экспорт в `out/`. `start` запускает его локальный просмотр на порту 3000; предварительно остановите dev-сервер. API-ключи не нужны. Зависимости зафиксированы в `package-lock.json`.

## Логотип и цвет

`public/brand/altum-logo.png` подготовлен из оригинального горизонтального PDF: обрезаны поля листа и удалён белый фон. Рисунок, надписи и пропорции сохранены. Оба исходных PDF в `public/brand/` не изменены.

Экранные цвета из оригинала после CMYK→RGB: красный `#B01528`, оранжевый `#F35E19`, жёлтый `#FCCB06`, графит надписи `#393536`. Для контрастных секций палитра расширена глубоким бордовым `#5B0D21` и его тёмными оттенками. RGB может немного отличаться в зависимости от цветового профиля и способа конвертации.

Чтобы заменить логотип, положите **оригинальный** SVG/PNG в `public/brand/`, измените `siteConfig.logo` в `src/lib/config.ts`. Ширина задаётся классом `.brand`, высота автоматическая. Не растягивайте и не генерируйте заново знак. Переменные палитры находятся в `:root` файла `globals.css`.

## Графика

Используемые файлы — в `public/art/`. Все сцены специально созданы для ALTUM и не содержат клиентских материалов, названий клиентов, вымышленных отзывов или показателей эффективности.

- `hero.webp` — треугольная стеклянная скульптура.
- `courses-v3.webp` — реалистичный экран электронного курса; предыдущий `courses.webp` сохранён как резерв.
- `training.webp` — цельный статичный постер бизнес-игры.
- `training-base.webp` + `knight.webp` — фон без коня и отдельная фигура для анимации.
- `digital.webp` — ноутбук и цифровые панели.
- `summit.webp` — фон блока преимуществ; `summit-team.webp` — финальная гора с четырьмя силуэтами людей.
- `*-small.webp` — небольшие варианты для responsive image loading.

Сохраняйте прозрачность у вырезанных сцен. Если меняете основное изображение, обновите и small-версию, `srcSet`, реальные пропорции и позиции живых слоёв. Сцены карточек — 3:2, конь — 2:3, гора — 16:9. У оригинальных файлов PNG есть резервная копия в каталоге ImageGen этой беседы; все рабочие WebP находятся непосредственно в проекте.

Полный prompt set и описание подготовки слоёв: `docs/art-direction.md`.

## Компоненты с анимацией

| Сцена                    | Реальное движение                                                                                                                   | Цикл              |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| `HeroScene`              | Дыхание объёмной композиции, три плавающие панели, световая орбита, деликатный pointer-parallax                                     | 10 с              |
| `ServiceScene: courses`  | Появление вопроса, перемещение курсора, выбор ответа, подтверждение и заполнение прогресса                                          | 8 с               |
| `ServiceScene: training` | Отдельный объёмный конь перемещается по композиции, камера приближается, появляются линии вариантов и панель решения, проходит свет | 9 с               |
| `ServiceScene: digital`  | Появление аналитической панели, рост столбцов, прорисовка графика, сборка AI-панели                                                 | 8 с               |
| `Interactions` / Why     | Подсветка и hover иконок преимуществ                                                                                                | 6 с               |
| `Interactions` / Process | Линия проходит через четыре этапа в зависимости от прокрутки                                                                        | По скроллу        |
| About                    | Сдвиг и лёгкий поворот объёмной скульптуры                                                                                          | 12 с              |
| Contact                  | Линия поднимается к вершине, появляется световой акцент, камера медленно приближается                                               | 9/18 с            |
| Reveal и UI              | Появление секций, hover-кнопки, мобильная навигация                                                                                 | По взаимодействию |

Таймлайны реализованы через `useAnimate` из Motion for React; [официальная документация](https://motion.dev/docs/react-use-animate). У каждой сцены свой управляемый timeline. IntersectionObserver останавливает невидимые сцены; background-вкладка, системный `prefers-reduced-motion` и ручная пауза также останавливают воспроизведение. На небольших экранах адаптируются размеры и число колонок, а pointer-parallax применяется только к точному указателю.

## Подключение motion-видео

Положите файлы в `public/videos/`, обновите `sceneMedia` в `src/lib/config.ts`:

```ts
courses: {
  webm: '/videos/courses.webm',
  mp4: '/videos/courses.mp4',
  poster: '/art/courses.webp',
}
```

Можно указать один или оба видеоформата. `ServiceScene` автоматически заменит программную сцену видео. Используются `muted`, `loop`, `playsInline`, `preload="none"`; воспроизведение запускается только в видимой сцене. При reduced motion и ручной паузе показывается статичный постер. Без видео остаётся текущая программная анимация.

Рекомендуется бесшовный цикл 6–9 секунд без звука, одинаковая композиция кадра и постера, WebM VP9 плюс MP4 H.264 для совместимости. После подключения обязательно проверьте Safari/iOS. Тяжёлые файлы следует оптимизировать; current-версия не зависит от видеозагрузки.

## Контакты

Заполните `src/lib/config.ts` подтверждёнными данными:

- `email` — рабочая почта.
- `phone` — телефон с кодом страны.
- `whatsapp` — только цифры, включая код страны.
- `address` — адрес, если его следует публиковать.

Все основные CTA открывают единую форму `ProjectForm`. Корпоративный адрес — `info@altum.kz`. Автоматическая доставка подключается сервером из `contact-service/`; без его настройки форма показывает доступную почтовую ссылку и не заявляет об отправке. Полная инструкция: `docs/form-integration.md`.

## Vercel

1. Загрузите каталог проекта в Git.
2. Создайте Project в Vercel → Import Git Repository.
3. Если загружен весь рабочий каталог, Root Directory: `altum-consulting`; если репозиторий начинается с этого каталога — корень.
4. Framework: Next.js. Install: `npm ci`. Build: `npm run build`. Сайт использует static export `out/`; серверные API не требуются.
5. Задайте `NEXT_PUBLIC_SITE_URL=https://подтверждённый-домен` и пересоберите проект.
6. Подключите домен, HTTPS и проверьте реальные контакты.

Если `NEXT_PUBLIC_SITE_URL` пуст, metadata запрещает индексацию временной версии (`noindex, nofollow`). После установки публичного адреса и повторной сборки включается индексация и canonical. Не заменяйте настоящий домен приватной ссылкой просмотра.

## Связь с iSpring

Партнёрский блок ведёт на https://altum-eta.vercel.app/. iSpring остаётся отдельным партнёрским предложением.

Исходников проекта iSpring в рабочем каталоге нет, существующий сайт не изменялся. Для обратного перехода перенесите `integrations/AltumCorporateLink.tsx` в проект iSpring, добавьте `<AltumCorporateLink />` в его навигацию и задайте `NEXT_PUBLIC_ALTUM_CORPORATE_URL` равным утверждённому публичному адресу ALTUM. Обратная ссылка начнёт работать после изменения и публикации самого проекта iSpring.

## Проверки и пределы проверки

Проверены TypeScript, production-сборка, браузерная навигация, мобильное меню, контактное окно (в предыдущих версиях — локальное сохранение брифа). На макетах 320/390/768 px проверена адаптивная компоновка. По реальным CSS-transform в браузере проверены движение отдельного коня, остановка невидимых сцен и ручная пауза. В консоли при проверке не обнаружены ошибки. Метрики Lighthouse и отдельные испытания Safari/iOS не выполнялись. Автоматическая почтовая доставка требует настройки серверного API; подтверждённый email уже указан.
