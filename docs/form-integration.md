# Форма обращения ALTUM

Все основные CTA открывают один нативный `<dialog>`. Карточки передают идентификатор направления: `courses`, `training`, `digital`. Для общей кнопки направление выбирает посетитель.

Обязательны имя, один контакт (телефон или email), направление и согласие. Компания и описание необязательны. Успех отображается только после ответа сервера с `delivered: true` и идентификатором принятого письма. При ошибке текст остаётся в форме. Повторная попытка использует тот же ключ идемпотентности, если данные не изменились.

## Текущее состояние

Подтверждённый получатель: **info@altum.kz**. Публичный адрес используется также в контактной ссылке. Ключ почтового провайдера, подтверждённый отправитель и адрес развёрнутого API не предоставлены. Поэтому на опубликованном статическом сайте отправка отключена, рядом с формой есть прямой email. Ни одно обращение не объявляется отправленным без подтверждения сервера.

## Подключение

Сайт сохраняет статический экспорт Next.js. Сервер вынесен в `contact-service/`, чтобы ключи и обработка персональных данных не попадали в статический архив сайта.

1. Создайте отдельный проект Vercel из той же Git-ветки с Root Directory `contact-service`, Framework Preset `Other`, без команды сборки. Его функция `/api/contact` использует Node.js и стандартные Request/Response.
2. В переменных **этого серверного проекта** задайте:
   - `CONTACT_EMAIL_TO=info@altum.kz`
   - `CONTACT_EMAIL_FROM` — согласованный адрес отправителя на подтверждённом в Resend домене
   - `RESEND_API_KEY` — секрет почтового API
   - `CONTACT_ALLOWED_ORIGINS` — точные origins сайта через запятую, без путей и завершающего `/`; включите текущий адрес Sites и будущий домен
3. Разверните сервер. В основном сайте задайте **перед сборкой** `NEXT_PUBLIC_CONTACT_ENDPOINT` равным полному HTTPS URL `/api/contact` этого проекта. Задайте `NEXT_PUBLIC_CONTACT_EMAIL=info@altum.kz` и `NEXT_PUBLIC_PRIVACY_URL` — адрес существующей согласованной политики. Политика в этой работе не создавалась и не изменялась.
4. Пересоберите и опубликуйте сайт. Выполните контрольную отправку и проверьте получение письма на корпоративном адресе. Ответ API означает принятие письма почтовым провайдером; последующее попадание во входящие нужно проверить отдельно.

Параметры с `NEXT_PUBLIC_` публичные, секретные ключи в них размещать нельзя. Сервер проверяет origin, формат и объём данных, обязательные поля, согласие и honeypot. Провайдер получает только данные обращения для доставки корпоративного письма. Внешние AI-сервисы не используются.

## Необязательные уведомления Telegram

В серверном проекте задайте секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Уведомление содержит только направление и номер обращения; имя, контакты и описание задачи остаются в корпоративном письме. Ошибка необязательного уведомления не отменяет уже принятое письмо и не вызывает ложную ошибку отправки.

## Проверки

`npm run test` проверяет сервер без реальной рассылки: отсутствие настроек, валидацию, неверный origin, preflight, отказ провайдера, тайм-аут, отсутствие квитанции, подтверждённое принятие письма и приватность Telegram-уведомления.

Документация API: [Resend Send Email](https://resend.com/docs/api-reference/emails/send-email), [Vercel Node.js Functions](https://vercel.com/docs/functions/runtimes/node-js).
